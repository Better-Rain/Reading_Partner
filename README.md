# Reading Partner

Reading Partner 是一个面向大部头 PDF 文献、英文原著和研究型阅读的桌面应用。它把 PDF 阅读、搜索定位、高亮、批注、书签、生词本、本地词典、AI 解释、文档问答和共读对话放在同一个工作流里，目标是让电脑成为一个可以陪你读书、查词、整理思路的阅读伙伴。

当前版本优先支持 Windows。第一版便携程序位于本地构建目录：

```text
release/Reading Partner 0.1.0.exe
```

双击即可运行，无需安装。

## 适合谁使用

- 阅读英文原著、论文、教材、技术文档，想随手查词和做笔记。
- 阅读长 PDF，希望搜索后能快速定位到页面中的具体文字。
- 想把选中的段落交给 AI 做翻译、解释、总结或继续追问。
- 想把高亮、批注和书签导出给别人，让对方在同一本 PDF 上复现你的阅读痕迹。
- 想保留本地优先的数据管理方式，避免把整本 PDF 默认上传给模型。

## 快速开始

1. 打开 `Reading Partner 0.1.0.exe`。
2. 点击左上角的打开按钮，选择一本 PDF。
3. 等待状态栏显示“文本索引完成”或“文本索引已就绪”。
4. 在右侧面板切换“笔记、搜索、AI、词汇、配置”开始使用。

首次配置 AI 时，进入“配置”面板，在 DeepSeek 或其他兼容服务中填写 API Key。API Key 保存在本机，不会进入 Git 仓库，也不会导出到阅读记录文件。

## 常见场景

### 场景一：阅读英文段落并让 AI 解释

1. 在 PDF 中拖选一段英文。
2. 浮动工具栏会出现“高亮、批注、翻译、解释、生词”等按钮。
3. 点击“解释”，AI 会根据选中文本生成解释。
4. 如果你想继续追问，进入右侧“AI”面板，新建或打开一个共读对话。

适合提问：

- “这段话的关键概念是什么？”
- “先分析句子结构，再解释思想含义。”
- “这段和上一节的论证关系是什么？”
- “请用中文解释，但保留重要英文术语。”

### 场景二：给重点内容做高亮和批注

1. 选中 PDF 原文。
2. 点击“高亮”保存荧光笔标记。
3. 点击“批注”写下自己的理解。
4. 鼠标移动到页面中的高亮或批注上，会显示悬浮提示。
5. 右侧“笔记”面板中可以展开、编辑、改颜色、跳转或删除。

快捷键：

- `H`：给当前选区添加高亮。
- `N`：打开当前选区的批注输入框。
- `D`：切换手型拖动模式。
- `Ctrl+Z`：撤销上一次批注、高亮或书签操作。

### 场景三：搜索文档并快速找到位置

1. 进入右侧“搜索”面板。
2. 输入关键词或短语。
3. 点击搜索结果。
4. 应用会跳到对应页，并用临时蓝色高亮标出命中位置。
5. 点击“结束”可以清空搜索结果并退出临时定位模式。

适合搜索：

- 某个术语：`swarm intelligence`
- 某个作者或概念：`paradigm shift`
- 某个缩写：`MAS`

### 场景四：查词和整理生词

1. 进入“词汇”面板。
2. 如果还没有词典，先导入本地 ECDICT 或 StarDict 词典。
3. 在词典搜索框中输入单词，应用会自动联想候选词条。
4. 点击候选词条可以查看音标、词性、释义、变形等信息。
5. 需要长期复习的词，可以加入当前 PDF 的生词本。

也可以在 PDF 中直接选中一个单词或短语，点击浮动工具栏中的“生词”，把它加入当前文档的生词本。

### 场景五：用共读对话持续追问

1. 进入“AI”面板。
2. 新建一个共读对话。
3. 输入第一条问题后，对话才会正式保存。
4. 应用会根据首条消息自动生成对话标题，也可以手动改名。
5. 后续问题会带着同一对话的上下文继续。

适合用法：

- 按章节建立对话，例如“第一章核心概念”“第三节公式推导”。
- 选中一段原文后提问，让 AI 同时参考选区和历史对话。
- 让 AI 帮你把一段话变成读书笔记，但自己再编辑保存。

### 场景六：和别人共享阅读记录

Reading Partner 支持导出和导入阅读记录，方便你把自己的阅读痕迹分享给别人。

导出：

1. 打开 PDF。
2. 进入“笔记”面板。
3. 点击“导出记录”。
4. 应用会生成一个 JSON 文件，里面包含高亮、批注、书签、颜色、时间和作者身份。

导入：

1. 对方先打开同一本 PDF。
2. 进入“笔记”面板。
3. 点击“导入记录”。
4. 选择你分享的 JSON 文件。

注意：阅读记录导出不包含 AI 对话、AI 生成内容和 API Key。

### 场景七：设置阅读身份

进入“配置”面板，找到“阅读身份”，填写自己的名字或昵称。之后新建的高亮、批注和书签都会带上这个身份，方便多人共享阅读记录时区分作者。

这个身份不是账号系统，也不用于安全认证，只是类似 Office 批注作者名的轻量署名。

## 数据与隐私

- PDF 文件路径、批注、书签、生词、搜索索引和 AI 对话记录默认保存在本机。
- 文档问答不会默认把整本书上传给模型，而是先从本地索引中检索相关片段。
- API Key 通过应用配置界面保存，不应写入 README、源码、文档或其他会提交到 GitHub 的文件。
- 导出的阅读记录只包含阅读标记，不包含 AI Key。

## 目前已知限制

- Windows 版本未做代码签名，首次运行可能出现系统安全提示。
- 便携版不会把用户数据保存在 exe 旁边，应用数据仍保存在系统用户数据目录。
- PDF 文本抽取依赖 PDF 本身的文字层；扫描版图片 PDF 需要后续 OCR 功能支持。
- 当前图标和安装包流程是第一版，后续可以补正式签名、安装器和自动更新。

## 给维护者的最少命令

普通用户不需要执行这些命令。只有在本地开发或重新打包时才需要：

```powershell
npm install
npm run dev
npm run typecheck
npm run dist
```

重新生成图标：

```powershell
npm run icons
```
